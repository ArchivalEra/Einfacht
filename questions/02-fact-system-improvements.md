# 02: 四条改进（来自一次真实维护的复盘，精简版）

**What to build:** 四条小改进。都来自 2026-10-01 一次真实批次的复盘（重测一次改了 3 条值、
一次静默缺陷靠 grep 日志才定位），按性价比排序，做完一条勾一条。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Settling:** sh gates-selftest.sh —— 全绿**且**本单四条各有自己的"该红"自证用例 ⇒ 逐条结案（勾掉对应条目，四条全勾即可删本单）；四条未全勾、或有条目拿不出反向用例 ⇒ 不结（本单保留）

**Type:** task

## ① `--accept-changes` 支持**逐条**（性价比最高）

重测一次改掉 N 条值时，现在只能全收或全拒。全收会把"真坏了的测量"一起洗白。
改法：`--accept-changes=k1,k2`（只接受列出的键），其余照旧拒绝。
自证用例：改 2 条只收 1 条 ⇒ 另 1 条必须仍拒绝。

## ② 事实带 `measured_at`，渲染块显示"多久没测了"

AUTO 块只有值和复跑命令，维护者看不出**哪条键老了**。采集时记时间戳（渲染成人话：
"3 天前测的"），`check_stale` 可选按天数报警（阈值可配，默认关）。
注意 `collect.py` 的契约：时间戳是**采集时刻**的记录，不许当成测量输入（否则 `--check` 永不收敛）。

## ③ 自证输出统一成一行机器可读摘要

各检查器的自证收尾格式不一，runner/CI 只能各写各的 grep。约定统一为
`=== N PASS / M FAIL ===`（与 PASS 行并存），`gates-selftest.sh` 与 hook 的解析随之简化，
新闸门照格式写即可被机器读。

## ④ `check_facts` 裸数字判据：阈值可配 + 代码块豁免

现在只查 ≥100 的整数（README 已记限制）。两条小改：阈值进配置（`REFLECT_NAKED_MIN`）；
 fenced code block / 行内代码里的数字豁免（文档里的复跑命令天然带数字，误报最烦的就是它）。
自证用例：代码块里的 `1234` 不报；正文里的 `1234` 报。

## 明确不做（本单范围外）

- 不改 `gates-selftest.sh` 的**发现式**机制（它是对的）；不引入任何配置文件之外的路径。
